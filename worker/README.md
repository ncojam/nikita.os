# Воркер «Находок»

Запускается на домашнем компьютере, не на сервере. Забирает с сайта плейлисты, примеры и голоса,
ищет свежие треки на YouTube и SoundCloud через yt-dlp (без YouTube API и его квоты) и отправляет
сайту ленту — до 20 треков на плейлист с оценкой и строкой «почему». Сайт сам никуда не ходит.

Сейчас оценка только по метаданным: теги и слова плейлиста, тот же артист, что в примерах и bump,
свежесть, отклик аудитории. Анализ звука добавится следующим шагом.

## Настройка (один раз)

1. На сервере задай ключ и перезапусти сайт: в `.env` рядом с `compose.yaml` строка
   `NOS_FINDS_TOKEN=<длинный случайный ключ>`, затем `./deploy.sh`.
2. Дома: `uv` (`sudo pacman -S uv`), конфиг:
   ```
   mkdir -p ~/.config/nos-finds
   cp worker/config.example.toml ~/.config/nos-finds/config.toml
   ```
   и впиши в него `token` (тот же ключ) и свой ник в `owner`.

## Запуск

```
uv run worker/finds_worker.py --test     # первый раз: до 3 плейлистов, не дольше 10 минут, с отчётом
uv run worker/finds_worker.py            # обычный прогон, лимит minutes из конфига (30 мин)
uv run worker/finds_worker.py --dry      # ничего не отправлять, только показать ленты
uv run worker/finds_worker.py -v         # подробно: какие запросы не удались
```

uv сам поставит yt-dlp во временное окружение по шапке скрипта — venv активировать не нужно.
Если YouTube начал отвечать капчей или ошибками, увеличь `sleep` в конфиге и запусти позже.
Если перестал работать поиск — обнови yt-dlp: `uv run --upgrade worker/finds_worker.py --test`.

## Как устроен прогон

1. `GET /api/finds/w/state` — все плейлисты, примеры, голоса.
2. Примеры: метаданные; у микса (длиннее 15 мин) — треклист из глав и описания, каждый трек
   ищется на YouTube и становится примером (в ленту сами эти треки не попадают).
3. Кандидаты: последние загрузки каналов и SoundCloud-артистов из примеров и bump, свежий поиск
   на YouTube и SoundCloud по названию плейлиста и частым тегам. Отсев миксов, подборок,
   разборов и уже показанного.
4. Разбор до 40 кандидатов на плейлист (потолок на пользователя за прогон, владелец — первым),
   оценка, `POST /api/finds/w/push` — после каждого плейлиста, чтобы прерванный прогон не пропал.

Кэш метаданных — `~/.cache/nos-finds/meta.db` (две недели), его можно просто удалить.
