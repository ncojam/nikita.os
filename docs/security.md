# Безопасность

Как сайт защищён, что проверено и что ещё осталось. Последнее ревью — 28.10.2026.

## Модель угроз

Сайт публичный, регистрация открыта любому. Значит, любой посетитель может:

- присылать произвольные запросы к API (клиентским проверкам не верим);
- выкладывать текст, картинки, папки и проекты DAWN, которые увидят другие;
- присылать ссылки на страницы сайта с подобранными параметрами;
- встраивать сайт в свой iframe;
- долбить дешёвые для него, но дорогие для сервера эндпоинты.

Ценное на сервере: аккаунты чата (сессии), чужой контент (его нельзя менять или удалять не автору), канон `fs/` (нельзя менять никому), журнал IP, токены `NOS_ADMIN_TOKEN`, `NOS_FINDS_TOKEN`, `TG_BOT_TOKEN`.

## Как устроена защита

### Файлы и пути
- `resolve_inside(root, rel)` — **единственный** путь из запроса на диск. Режет `..`, выход через симлинки, `\0` и любые сегменты с точкой.
- Всё служебное лежит в `.meta/` и поэтому не отдаётся через `/fs`.
- Канон `fs/` в Docker смонтирован `:ro`. Даже взломанный сервер не может его изменить.
- Пользователь кладёт в `/ufs` только папки и файлы `.dawn` (JSON формата `dawn/2`). HTML, SVG и скрипты загрузить нельзя, `nosniff` не даст браузеру угадать другой тип.

### Аккаунты
- Пароли хранятся в scrypt (`n=2^14, r=8, p=1`) с солью, сравнение за постоянное время.
- Сессия — случайный токен в cookie `nos_chat` с флагами `HttpOnly`, `SameSite=Strict` и `Secure` за HTTPS. `SameSite=Strict` заодно закрывает CSRF для всех POST/PATCH/DELETE.
- WebSocket (`/api/chat/ws`, арена) проверяет `Origin`.
- Неудачные входы ограничены: 10 за 10 минут с одного IP. Регистрация — одна с IP в 30 дней.
- Истёкшие сессии удаляются фоновой задачей раз в 6 часов (`Chat.cleanup`).

### Чужой контент в браузере
- Чат, комментарии, записи выводятся только через `textContent`.
- Markdown форума (`browser.js: md`) сначала экранирует всё, потом размечает. Картинки — только `/media/...`, ссылки — только `http(s)://`.
- Картинки проверяются без декодирования: магия JPEG, потолок размера, размеры из заголовка SOF.
- Код DSP из проекта DAWN выполняется в AudioWorklet: там нет DOM, сети и cookie.

### Встраиваемые проигрыватели
- **Flash** (`apps/flash.html`) открывает только `.swf` с этого же сайта из `/fs/`. Чужой SWF на нашем origin ходил бы в API с cookie посетителя, то есть действовал бы от его имени.
- **GBA** может загрузить ром по внешней ссылке (`?url=`). Это сознательно: ром выполняется внутри эмулятора и не имеет доступа к странице.

### HTTP-заголовки (`server.py: add_headers`)
| Заголовок | Значение | Зачем |
|---|---|---|
| `Content-Security-Policy` | `frame-ancestors 'self' https://zcojam.neocities.org` (+ `https://web.telegram.org` для `/tg.html`) | Встраивать сайт в iframe можно только себе и neocities — защита от кликджекинга |
| `Content-Security-Policy-Report-Only` | полная политика (`CSP_REPORT_ONLY`) | Пока только отчёты в консоли; см. «Что осталось» |
| `Cross-Origin-Opener-Policy` / `-Embedder-Policy` | `same-origin` / `require-corp` | Нужно mGBA (SharedArrayBuffer); на `/tg.html` и `/finds` нет — им нужны внешние скрипты и плееры |
| `Cross-Origin-Resource-Policy` | `same-origin` | Чужие сайты не встроят наши файлы |
| `X-Content-Type-Options` | `nosniff` | Браузер не угадывает тип файла |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | Пути страниц не утекают наружу |
| `Server` | `nikita.os` | Не светим версии Python и aiohttp |

Чтобы разрешить встраивание ещё куда-то, допиши адрес в `FRAME_ANCESTORS`.

### Служебные токены
- `NOS_ADMIN_TOKEN` (модерация) — только в заголовке `Authorization: Bearer <токен>`. В адресной строке он оседал бы в логах nginx и aiohttp и в истории браузера, поэтому `?token=` не принимается.
  ```bash
  curl -H "Authorization: Bearer $NOS_ADMIN_TOKEN" https://сайт/api/mod/reports
  ```
- `NOS_FINDS_TOKEN` (домашний воркер) — заголовок `X-Finds-Token`.
- Оба сравниваются через `compare_digest`. Если токен не задан, эндпоинты отвечают 404, как будто их нет.
- Подпись `initData` Telegram проверяется HMAC по `TG_BOT_TOKEN`, старше суток не принимается.

### Нагрузка и лимиты
| Что | Защита |
|---|---|
| Медленные соединения | таймауты заголовков и тел в nginx/Caddy, `keepalive_timeout` в aiohttp |
| Частота запросов | nginx: 50 запросов/с и 50 соединений с IP |
| Размер тела | nginx 64 КБ (3 МБ для `/api/dawn/save`), aiohttp 2,5 МБ |
| `POST /api/visit` | 30 запросов в минуту с IP; на диск раз в 30 с; ≤ 200 000 уникальных и ≤ 64 счётчика |
| `GET /api/find` | кэш на 60 с, один обход `fs` одновременно, ≤ 20 расширений в запросе |
| `/grab` | ≤ 48 «загрузок» всего, ≤ 3 с IP, ≤ 30 минут каждая |
| Контент пользователей | лимиты на аккаунт и потолки складов, см. [social.md](social.md) |

### Контейнер
Корневая ФС только для чтения, пользователь без прав (UID 10001), `cap_drop: ALL`, `no-new-privileges`, лимиты памяти и процессов. Порт приложения открыт только на `127.0.0.1`.

### IP посетителя
- `client_ip()` берёт `X-Forwarded-For` (последний адрес) только при `TRUST_PROXY=1`. Это безопасно, **только пока приложение недоступно напрямую**: иначе любой подставит себе IP и обойдёт все лимиты.
- Проверка на сервере:
  ```bash
  ss -tlnp | grep 8000                        # должно быть 127.0.0.1:8000
  docker ps --format '{{.Names}}  {{.Ports}}' # должно быть 127.0.0.1:8000->8000/tcp
  ```
  и снаружи: `curl -m 5 http://<ip-сервера>:8000/` должен падать.
- Docker обходит ufw: защищает именно привязка `127.0.0.1` в `compose.yaml`, не файрвол.

## Персональные данные

| Что | Где | Сколько хранится |
|---|---|---|
| IP при регистрации и входе | `chat.db: ip_log` | 180 дней (`IP_KEEP` в `chat.py`) |
| IP последнего входа, IP регистрации | `chat.db: users` | пока есть аккаунт |
| IP автора сообщения/комментария | `chat.db: messages`, `comments` | пока живёт сообщение (чат хранит последние 1000) |
| IP в плейлистах и голосах | `finds.db` | бессрочно |
| IP загрузившего картинку записи | `posts.json` — только солёный хэш | пока есть запись |
| Прослушивания | `plays.json` — только счётчики; хэши IP в памяти до перезапуска | — |
| Посетители счётчика | `visits.json` — хэши случайного id браузера | — |

Личные сообщения через сервер не идут (WebRTC P2P), сервер сводит собеседников только после взаимного согласия.

## Что осталось сделать

Средний приоритет:
- **Включить CSP.** Пройтись по сайту (Flash, GBA, Unity-игры, «Находки», DAWN, Telegram Mini App) с открытой консолью. Если отчётов о нарушениях нет, переименовать `Content-Security-Policy-Report-Only` в `Content-Security-Policy` (переменная `CSP_REPORT_ONLY`).
- **Перебор паролей:** добавить лимит по нику (сейчас только по IP) и поднять минимум пароля до 8.
- **IP в `messages`, `comments`, `finds.db`** — чистить по сроку, как `ip_log`.

Низкий приоритет:
- Удаление пользовательской папки оставляет чужим проектам DAWN записи в `projects.json` — чистить по префиксу.
- Ники из Telegram (`first_name`) не очищаются и могут совпасть с ником аккаунта.
- Спрашивать перед запуском DSP-кода из чужого проекта DAWN: бесконечный цикл повесит звук.
- nginx режет тела до 64 КБ, а форум принимает картинки до 120 КБ — нужен отдельный `location`.
- HSTS в nginx: `add_header Strict-Transport-Security "max-age=31536000" always;`.

## Обслуживание
- Пересобирать образ с `--pull`, чтобы подтягивать обновления Python, и время от времени поднимать версию aiohttp в `requirements.txt`.
- Обновлять систему VPS, включая OpenSSH.
- Секреты — только в `.env` на сервере (он в `.gitignore`), никогда в репозитории.
- После подозрения на утечку — сменить токен и перезапустить контейнер: `docker compose up -d`.
