# Семейство nikita.os

Планируемые приложения: `ncojam/dawn.os`, `ncojam/kana.os`, `ncojam/clown-dungeon.os`.
Каждое подключается Git submodule в `modules/<name>`, на конкретном коммите.
До появления `modules/.enabled` ничего не меняется в запуске существующего сайта.

## Переход без изменения URL и данных

- В дочерних репозиториях на первом этапе сохраняются исходные относительные пути. `tools/materialize_modules.py` раскладывает файлы в прежние места перед локальным запуском и сборкой Docker. Это позволяет сохранить ES imports, lazy loader, WebSocket, API, Telegram Mini App, TTS и файловые форматы.
- `modules/layout.json` определяет, какие пути принадлежат каждому приложению. После активации эти пути в корне — генерируемые копии, редактировать нужно исходники в submodule.
- DAWN и Dungeon используют одну копию движка DAWN; игровой код продолжает импортировать graph/format/fx/instruments по старым путям. Публичный API движка и SDK ОС — отдельный последующий рефакторинг.
- Общие окна, системный звук, шина сигналов, авторизация, seed-ярлыки, пользовательские файлы, посещения и данные остаются в nikita.os. Серверные маршруты пока регистрирует server.py.
- Docker, Python и браузер не обращаются к GitHub за кодом во время работы сайта.

## Одноразовое разделение

На чистой актуальной ветке main после слияния подготовительного PR:

```sh
# Требуются git-filter-repo и GitHub CLI (gh); авторизоваться и настроить git credentials.
gh auth status
gh auth setup-git
python3 tools/split_modules.py
```

Без параметров скрипт только выделяет историю в временные локальные репозитории и сравнивает
все пути, режимы и blob SHA с исходным деревом, включая бинарные модели.
Для фактического создания публичных репозиториев и подготовки новой ветки:

```sh
python3 tools/split_modules.py --publish
```

Скрипт не перезаписывает непустые сторонние репозитории, не force-push, не меняет main,
не трогает fs/, data/ или том Docker и не выполняет деплой. Если публикация прошла частично,
повторный запуск принимает уже опубликованный идентичный коммит, но не чужую историю.
После выполнения проверь staged diff, прогони тесты, запусти сайт локально, проверь Кану,
DAWN и Clown Dungeon, затем закоммить и открой PR из refactor/split-os-apps.

## Работа после миграции

```sh
git submodule update --init --recursive
python3 tools/materialize_modules.py
python3 -m unittest discover -s tools -p 'test_modules.py'
```

Обычный deploy.sh получает зафиксированные коммиты submodules. Для прямого docker compose
build предварительно инициализируй submodules. run.sh не переключает их версии автоматически,
чтобы не сбрасывать локальную разработку. После правок в приложении закоммить и отправь их
в репозиторий приложения, затем зафиксируй новую ссылку на коммит в nikita.os.

История фильтруется по указанным путям, хеши коммитов закономерно меняются; исходная история
остаётся в nikita.os. Исторические переименования за пределы layout требуют отдельной проверки.
