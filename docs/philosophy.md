# Философия и сквозные механизмы

## Принципы

- **Без фреймворков и сборки.** Нативные ES-модули, `el()` вместо JSX, CSS одним файлом. Открыл файл — видишь, что выполняется.
- **Канон неприкосновенен.** `fs/` — авторский контент, сайт его не меняет никогда (в Docker смонтирован `:ro`).
  Всё пользовательское живёт отдельно: общее — в `NOS_DATA/ufs`, личное — в браузере посетителя.
- **Два уровня «своего»:**
  - *локально* — VFS: посетитель двигает, удаляет, грузит файлы, создаёт черновики. Видит только он, сервер не знает;
  - *общее* — записи, папки `/ufs`, чат, форум: видят все, правила и лимиты — на сервере.
- **Приложения не знают про слои.** Любое приложение (включая игры в iframe) читает `/api/ls` и `/fs/...` — Service Worker и сервер сами сшивают канон, общее и личное.
- **Сервер не доверяет клиенту.** Клиент жмёт картинки и проверяет поля для удобства; сервер всё равно валидирует (размер, магия JPEG, размеры из заголовка, длины, частота).
- **Приватность по умолчанию.** Личка — P2P (WebRTC), текст через сервер не идёт. IP в модерации — солёный хэш. Внутреннее хранилище — в `.meta`, которое веб не отдаёт.
- **Дёшево и с потолками.** Каждое хранилище имеет лимит (на пользователя, на склад) и чистится по старшинству. Всё регулируется переменными окружения `NOS_*`.
- **С юмором.** «Загрузчик» GTA VI, который не докачается, — тоже часть проекта (см. [apps.md](apps.md)).

## Сквозные механизмы

| Механизм | Где | Суть |
|---|---|---|
| Единый аккаунт | `chat.py: user_by_token` | HttpOnly-cookie `nos_chat` → `(uid, nick)`. Им пользуются записи, папки, комменты, форум, Джус |
| Регистрация = вход | `POST /api/chat/auth` | Нет ника — создаём, есть — входим. 1 регистрация с IP в 30 дней |
| Сшитая ФС | `server.py: api_ls / serve_fs` | `/fs` (главнее) + `/ufs` + виртуальные `.запись` в одном списке |
| Личный слой | `overlay-core.js` + `sw.js` + `core/vfs.js` | IndexedDB-оверлей поверх ответов сервера (см. [filesystem.md](filesystem.md)) |
| Инструмент сжатия картинок | `apps/post.js: shrink / pickImage` | canvas → JPEG с понижением качества до лимита. Параметры `dim`, `limit`: записи 256px, аватарки 256px, посты форума 800px |
| Проверка JPEG без декодирования | `posts.py: jpeg_dims / validate_jpeg`, `forum.py: check_jpeg` | магия `FFD8FF`, потолок байт, ширина/высота из SOF |
| Антиспам по частоте | `posts.py`, `chat.py`, `forum.py` | временные метки на `uid` в памяти/данных |
| Чистка текста | `clean_text` / `clean_md` | убираем управляющие, невидимые и bidi-символы |
| Безопасный вывод | клиент | чужой текст — только `textContent`; Markdown форума — сначала экранирование, потом разметка |
| Событие «поменялось» | `nos-posts-changed` | `{detail:{dir}}` — рабочий стол и проводники перечитывают папку |
| Атомарная запись на диск | все `save()` | пишем `*.tmp` → `os.replace` |
| Заголовки безопасности | `server.py: add_headers` | COOP/COEP (нужно mGBA для SharedArrayBuffer), CORP, nosniff; `/tg.html` — без COOP/COEP |
| Настройки посетителя | `core/util.js: store` | `localStorage` с JSON и try/catch |
| Настройки по умолчанию | `fs/etc/*.json` | `os.json` (обои), `gba.json` (эмулятор) — создаются один раз, дальше правятся руками |
